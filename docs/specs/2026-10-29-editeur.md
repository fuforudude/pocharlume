# Éditeur de retouche des designs

Statut : livrée le 2026-10-30 (en parallèle du jalon 5)
Date : 2026-10-29

## Besoin
L'utilisateur veut retoucher lui-même les designs faits par les agents (sprites, couleurs, décors des cartes), sans
écrire les fichiers texte à la main, et voir le résultat tout de suite. L'outil doit aussi servir sur d'autres
projets : il est découpé en un cœur générique et un adaptateur par projet.

## Décisions (entretien du 2026-10-29)
- Outil local, sur le PC, dans le navigateur : `npm run editeur` (serveur de développement en localhost). Jamais en ligne,
  jamais dans le build du jeu.
- Il lit et réécrit directement les sources : `art/sprites/*.txt` (calques, animations), la palette, et les données des
  cartes (décors, statues). Après un enregistrement, l'atlas est reconstruit (`npm run art`).
- Cœur générique et adaptateur (ajouté le 2026-10-29) : le cœur (`tools/atelier/`) ne connaît aucun projet ; il n'importe rien de `src/` ni de `tools/art/` et peut être copié tel quel dans un autre dépôt ou en sortir. Il ne dépend que d'une interface d'adaptateur (liste des sprites, calques, rendu des cadres, palette, objets d'une grille avec leurs règles, droits d'écriture, commande après écriture). L'adaptateur Pocharlume (`tools/atelier-pocharlume/`) la remplit ; un adaptateur d'exemple minimal (format texte `.pix`, `tools/atelier/exemple/`) prouve que le cœur sert à autre chose. Chaque projet a un `atelier.config.ts` à la racine (adaptateur, port) que `npm run editeur` lit.
- L'utilisateur prévient, Claude relit (tests, sprites dérivés comme Mastoc ou l'assassin d'ombre), commite et pousse.
  L'outil ne commite ni ne pousse.

## Périmètre
- Cœur : éditeur de pixels (calques, pinceau, gomme, pipette, annuler, zoom), aperçu d'animations, palette, vue de grille 2D pour placer des objets, serveur local qui lit et écrit des fichiers par l'intermédiaire de l'adaptateur. Documentation de l'interface d'adaptateur dans `tools/atelier/README.md`.
- Sprites : choisir un sprite et un calque, peindre et gommer au pixel avec les lettres de la palette, pipette, annuler
  et rétablir, zoom, grille. Ajouter ou retirer un calque n'est pas demandé.
- Animations : chaque animation du sprite jouée à taille réelle et agrandie, sur le sol du jeu, mise à jour pendant la
  retouche. Liste des sprites qui dérivent de celui-ci (`derive`, `modele`), avec leur aperçu, pour voir l'effet.
- Palette : changer la couleur d'une lettre et voir tous les sprites concernés changer ; avertissement si la couleur
  sert à beaucoup de sprites.
- Cartes : déplacer les décors et la statue d'une carte sur la grille des cases. Les règles du jeu s'appliquent en
  direct (pas sur le chemin, emprise des grands décors, statue sur une case de décor) ; le nombre de cases
  constructibles avant et après est affiché, avec l'avertissement qu'un changement de carte peut demander de
  rééquilibrer.
- Hors périmètre : créer un nouveau sprite, une nouvelle carte, modifier les chemins, les vagues ou l'équilibrage.

## Critères d'acceptation
- [x] `npm run editeur` ouvre l'outil ; il n'apparaît pas dans `npm run build` ni sur le site.
- [x] Ouvrir un sprite, changer un pixel, enregistrer : le fichier `.txt` ne change qu'à cet endroit (le reste du
  fichier, commentaires compris, est conservé à l'identique), et l'atlas est reconstruit.
- [x] Ouvrir puis enregistrer sans rien changer laisse tous les fichiers identiques octet pour octet (test sur les 66).
- [x] L'aperçu des animations se met à jour à chaque coup de pinceau.
- [x] Changer une couleur de palette met à jour l'aperçu de tous les sprites qui l'utilisent.
- [x] Déplacer un décor sur une case interdite (chemin) est refusé avec un message ; une carte enregistrée passe les
  tests de cartes existants.
- [x] L'outil n'écrit que dans `art/` et dans les fichiers de données des cartes ; il refuse tout autre chemin.
- [x] Le cœur ne dépend pas de Pocharlume (test `tools/atelier/isolation.test.ts`) et un second adaptateur d'exemple marche (`tools/atelier/exemple/exemple.test.ts`).
- [x] Statue : emplacement prévu dans l'interface et l'adaptateur, branché à la fusion avec `j5-statues` : chaque carte montre sa statue, déplaçable sur une case de décor seulement (règles de `src/data/niveaux/statues.test.ts`, refus avec un message), seule sa ligne de `src/data/niveaux/statues.ts` est réécrite (test `tools/atelier-pocharlume/statues.test.ts`) ; sans ce fichier, désactivée avec un message.

## Tâches
0. Découpage cœur générique / adaptateur (interface, configuration par projet, adaptateur d'exemple).
1. Lecture et écriture sans perte des sources de sprites et de palette (aller-retour testé sur tous les fichiers).
2. Serveur local (petit plugin du serveur de développement) : liste, lecture, écriture limitée aux dossiers permis,
   reconstruction de l'atlas.
3. Interface sprites : calques, pinceau, gomme, pipette, annuler, zoom ; aperçu des animations et des dérivés.
4. Palette.
5. Cartes : décors et statue, règles en direct, écriture sans perte des données de carte.
6. Relecture, QA au navigateur.

## Impacts
- Aucun sur le jeu publié. Nouveau script `npm run editeur`, dossiers `tools/atelier/` (cœur) et `tools/atelier-pocharlume/` (adaptateur), fichier `atelier.config.ts`.
